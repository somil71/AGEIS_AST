# Fix Brief: Policy Audit Gap + Verification Debt — Pre-SIH Submission (Due Aug 17)

## Context

This is the air-gapped AST code & policy auditor for SIH 2026. A review of the 35-question Q&A pass surfaced two categories of problems:

1. **Product gap:** "Policy" is half the project's name, and the problem statement explicitly names "sensitive legal policies" alongside legacy codebases. But only 1 of 35 answers touches policy auditing, it's a single toy example (SHA-1 vs SHA-256 string match), and the live demo script never shows it. If a judge reads the title before the demo, this is the first thing they'll ask to see.
2. **Verification debt:** several answers state specific numbers (latency, precision/recall, binary size, cold-start time) with no artifact behind them. These need to become real measurements, not confident-sounding estimates.

**Rule for this entire task: every item below needs a runnable artifact, not a paragraph.** If something can't be finished in time, say so directly instead of writing a status update that sounds more complete than it is.

## P0 — Must fix before Aug 17

### 1. Build a real, repeatable policy-contradiction demo
- Write one short policy document (markdown or PDF, 1–2 pages, can be synthetic but should read like a real internal security circular) with at least 3 concrete clauses — e.g. token expiry limits, hashing algorithm requirements, PII logging restrictions.
- Write one code sample that violates at least **2 distinct clauses in non-trivial ways** — not just an algorithm-name string match. Example: a token issuance function with no expiry check, plus a log statement that dumps a PII field.
- Wire the full path: policy doc → embed → index; code → embed → index; query layer cross-references both and surfaces the specific clause + specific code location in conflict.
- Deliverable: a single script or CLI command that runs this end-to-end from a clean state and prints the flagged contradictions. Must be runnable live without manual setup on stage.

### 2. Insert the policy step into the live demo script
- Add a policy-audit step to the existing 5-step demo flow.
- Rewrite the talking points so policy auditing is explicitly shown as core functionality, not implied by the product name.

### 3. Resolve the naming inconsistency
- Pick one name: "Sentinel Auditor" or the current binary name `needle-app.exe`. Whichever is chosen, update it everywhere — binary filename, window title, taskbar/tooltip, README, pitch deck.

## P1 — Should fix, credibility risk under Q&A

### 4. Replace the latency claim with a real benchmark
- Write a benchmark script: ≥50 queries against the current index at whatever repo size is actually loaded. Log index-traversal time, embedding-generation time, total time, and repo size (files/LOC) at time of test.
- Report the actual measured numbers. If they land near the previously stated ~20–30ms, good — but there needs to be a script behind the claim.

### 5. Build a real precision/recall test set
- Assemble 15–20 code snippets: roughly half genuinely vulnerable (real CWE patterns — hardcoded secret, SQLi, unchecked eval, missing auth check), half clean but superficially similar, so the test isn't trivial.
- Run the current pipeline against all of them and log true positives, false positives, false negatives, true negatives.
- Report actual precision/recall/F1 — an honest "8/10 caught, 3 false positives" is stronger under Q&A than an unquantified "phenomenally high recall."

### 6. Verify binary size and cold-start time
- Run a fresh `cargo tauri build` and report actual binary size from the filesystem, not an estimate.
- Time actual cold start (launch → ready to query) on the machine that will be used for the demo, averaged over 3 runs.

### 7. Make legacy-language handling an explicit, demoed feature
- Take a file in a language without a wired tree-sitter grammar (or deliberately malformed syntax in a supported language) and show it still gets ingested via the raw-text fallback path.
- Add one line to the pitch: "unsupported or legacy syntax degrades to full-text indexing instead of failing" — backed by this demo, not left as a hidden error-handling detail.
